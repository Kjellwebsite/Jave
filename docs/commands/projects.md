# Discord: projects & contributions

Feature `apps/bot/src/features/projects` · custom-id namespace `projects` ·
domain: `@jave/core` `projects` (see [docs/modules/projects.md](../modules/projects.md)).

Every reply is **ephemeral** unless noted. Custom ids route; they never
authorize — each handler calls core as the clicking user, so forged or stale
ids fail closed (`NOT FOUND`, `ACCESS RESTRICTED`, `STALE` or `EXPIRED`).
Private and invisible projects always answer _not found_, never _forbidden_.

## Slash commands

| Command                                                | Who                                                            | What it does                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------------------------------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/project create`                                      | member in good standing                                        | Opens the **START A PROJECT** modal: title, summary, description, visibility select (MEMBERS default, PUBLIC, PRIVATE), domain select. The project starts at IDEA; the author is owner.                                                                                                                                                                                                                       |
| `/project view project:<autocomplete> [share]`         | anyone who can see the project                                 | Project card: status pipeline `IDEA → PLANNING → ▸ BUILDING → TESTING → SHIPPED`, team (hidden profiles counted, not named), milestones `2/5 done`, links, about. `share:true` posts it **publicly**, only for PUBLIC projects (others answer NOT SHARED, privately), with only the dashboard link button, rendered for the public audience: only members with a public profile are named, whoever shares it. |
| `/project list [status] [mine]`                        | everyone                                                       | Paged list (10 per page) with an **Open a project** select, a **Filter by status** select and PREVIOUS / NEXT buttons.                                                                                                                                                                                                                                                                                        |
| `/project status project:<autocomplete>`               | owner, maintainer, `canManageProjects`                         | **Move to…** select of the transitions allowed from the current status (core's table). ARCHIVED is offered to owners/staff only and asks for confirmation.                                                                                                                                                                                                                                                    |
| `/project milestone add project:<…>`                   | owner, maintainer, staff                                       | **ADD MILESTONE** modal: milestone, details, due date (`YYYY-MM-DD`, UTC).                                                                                                                                                                                                                                                                                                                                    |
| `/project milestone done project:<…> milestone:<…>`    | owner, maintainer, staff                                       | Marks an open milestone done. The milestone option autocompletes open milestones of the chosen project only.                                                                                                                                                                                                                                                                                                  |
| `/project member add project:<…> member:<user> [role]` | owner/staff (any role); maintainer (contributors only)         | Adds the member (default CONTRIBUTOR). They are notified and can leave at any time. There is no join request: the module has no invitation step.                                                                                                                                                                                                                                                              |
| `/project member remove project:<…> member:<user>`     | owner/staff; maintainer (contributors only)                    | Removes the member. Their recorded contributions stay.                                                                                                                                                                                                                                                                                                                                                        |
| `/contribute add [project:<autocomplete>]`             | yourself (good standing)                                       | **RECORD CONTRIBUTION** modal: kind select, what you did, link (http(s)), details. The project option autocompletes **your** projects; attaching to a project you are not on is refused.                                                                                                                                                                                                                      |
| `/contribute list [member] [status]`                   | everyone                                                       | Contributions of a member (default you). Others see only VERIFIED work of visible profiles on visible projects; review notes only for the author and reviewers.                                                                                                                                                                                                                                               |
| `/contribute review`                                   | `canVerifyContributions`, or owner/maintainer (their projects) | The review queue, one card at a time: **VERIFY** · **REJECT** · **SKIP**. Your own contributions never appear.                                                                                                                                                                                                                                                                                                |

Autocomplete (`project` options) lists the invoking user's visible projects
(`view`) or the projects they can manage (`status`, `milestone`, `member`;
staff see every project), newest activity first, 25 at most.

## Context menus

| Menu                                     | Who                                                  | Flow                                                                                                                                                                                                                                                     |
| ---------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| User → Apps → **Add to Project**         | owners/maintainers of an active project; staff (all) | Select of the projects you can edit that the member is not on yet (25 newest) → role buttons (MAINTAINER only for owners/staff) → core adds them. Bots and users without a JVLN profile answer NOT FOUND; nothing to offer answers NO PROJECT TO ADD TO. |
| Message → Apps → **Record Contribution** | the message's author (yourself)                      | Opens **RECORD CONTRIBUTION** prefilled with the message's first line (3–200 characters) and its jump link, no project. Someone else's or a webhook's message answers **NOT YOUR MESSAGE**.                                                              |

The project card offers the same flow the other way round: **ADD MEMBER** →
Discord's member picker → role buttons. Every step re-authorizes the clicking
user through core, so a forged select value or button for a project you do not
manage answers ACCESS RESTRICTED (or NOT FOUND for projects you cannot see).

## Buttons, selects and modals

| Custom id                                                                                                                      | Surface                                  | Handler                                                                                  |
| ------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- | ---------------------------------------------------------------------------------------- |
| `projects:view:<projectId>`                                                                                                    | VIEW PROJECT / CANCEL                    | Re-renders the card for the clicking user.                                               |
| `projects:open` (select)                                                                                                       | list → Open a project                    | Card of the selected project.                                                            |
| `projects:filter:<scope>` (select)                                                                                             | list → Filter by status                  | Re-renders the list page 1.                                                              |
| `projects:list:<scope>:<status>:<offset>`                                                                                      | PREVIOUS / NEXT                          | Re-renders that page.                                                                    |
| `projects:status:<projectId>`                                                                                                  | card → STATUS                            | Status picker.                                                                           |
| `projects:setstatus:<projectId>:<from>` (select)                                                                               | status picker                            | `changeProjectStatus`; answers **STALE** if the project moved since the picker opened.   |
| `projects:archive:<projectId>:<from>`                                                                                          | ARCHIVE confirmation                     | Archives (owner/staff).                                                                  |
| `projects:msadd:<projectId>`                                                                                                   | card → ADD MILESTONE                     | Opens the milestone modal (modal id `projects:msadd:<projectId>` → `addMilestone`).      |
| `projects:msdone:<projectId>` → `projects:msdonesel:<projectId>`                                                               | card → COMPLETE MILESTONE → select       | `completeMilestone`.                                                                     |
| `projects:contribute:<projectId>`                                                                                              | card → RECORD CONTRIBUTION               | Opens the contribution modal (modal id `projects:contribute:<projectId\|none>`).         |
| `projects:leave:<projectId>` → `projects:leaveok:<projectId>`                                                                  | card → LEAVE → confirmation              | `leaveProject` (owners must transfer first).                                             |
| `projects:addmember:<projectId>` → `projects:addpick:<projectId>` (user select) → `projects:add:<projectId>:<memberId>:<role>` | card → ADD MEMBER → member picker → role | `addProjectMember`; the picked user must have a JVLN profile and not be on the team yet. |
| `projects:addto:<memberId>` (select) → `projects:add:<projectId>:<memberId>:<role>`                                            | Add to Project menu → project → role     | `addProjectMember` with the chosen role.                                                 |
| `projects:cq:<index>`                                                                                                          | review queue SKIP / NEXT / START OVER    | Re-reads the queue (never cached) and shows item `index`.                                |
| `projects:cverify:<contributionId>:<index>`                                                                                    | VERIFY                                   | `verifyContribution` → becomes accepted evidence; the author is notified.                |
| `projects:creject:<contributionId>:<index>`                                                                                    | REJECT → reason modal                    | `rejectContribution` with the reason (3–1000 characters); the author reads it.           |
| `projects:create` (modal)                                                                                                      | START A PROJECT                          | `createProject` (≤ 5 per day, ≤ 20 active owned).                                        |

Unknown actions (retired or forged) answer **EXPIRED — This control is no
longer active.** User text on cards is markdown-escaped and mention-neutralized
(`userText()`); only http(s) URLs up to 512 characters are rendered.

## Discord permissions

No channel permissions are needed for ephemeral replies. `share:true` posts
the card as the interaction's public reply (the bot needs the channel to allow
application commands). The feature defines no `discord.*` jobs: the projects
module has no Discord side effects of its own.

## Dashboard

| --------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/projects`                 | every signed-in user (core filters visibility) | Status tabs (Active · Idea · … · Archived), search, scope (all / mine), sort, grid or list layout, pagination.                                                                       |
| `/projects/new`             | members in good standing                       | Create form; redirects to the new project.                                                                                                                                           |
| `/projects/[slug]`          | anyone who can see it (else 404)               | Header with status badge, CHANGE STATUS (managers), RECORD CONTRIBUTION (members); lifecycle strip; tabs Overview · Team · Milestones · Links · Contributions · Activity · Settings. |
| `/projects/[slug]?tab=team` | managers act; everyone reads                   | Add by handle, change role, make owner (transfer), remove, leave.                                                                                                                    |
| `?tab=settings`             | owner, maintainer, staff                       | Details (visibility for owner/staff), GitHub repository link, archive; staff restore archived projects with a reason.                                                                |
| `/contributions`            | everyone                                       | Review queue (VERIFY with optional note / REJECT with reason), Mine, Verified; RECORD CONTRIBUTION dialog.                                                                           |
